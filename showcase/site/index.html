03 / Behind the interface

Built around traceability.

Explore the repository ↗

The real Python project carries source identity through each transformation. This static desk illustrates the search and answer experience using public fixture text.

  1. 01 / Ingest

    Bound the input.

    PDF, PNG, JPEG validation, resource limits, and SHA-256 identity.

    pypdf · Pillow
  2. 02 / Extract

    Read each page.

    Embedded PDF text first. Route eligible pages to local OCR.

    PDFium · RapidOCR · ONNX
  3. 03 / Structure

    Keep its place.

    Positioned text, line-based PDF tables, and page-bounded chunks.

    pdfplumber · provenance
  4. 04 / Retrieve

    Find the evidence.

    Transparent lexical BM25 ranking over verified corpus chunks.

    Unicode tokens · no vector index
  5. 05 / Answer

    Cite or abstain.

    Exact retrieved excerpts with page, region, and character offsets.

    Extractive · no LLM
  6. 06 / Evaluate

    Make it measurable.

    Text, retrieval, answer, and citation metrics with explicit quality gates.

    Fixtures · gates · regressions
The real local product

One trusted operator.

The original Evidence Desk talks to an authenticated loopback JSON API. A separate worker handles durable SQLite jobs and a content-addressed artifact store.

Local deployment boundary ↗
This public demonstration

Static files. Browser interaction.

A bundled two-page sample → browser BM25 illustration → exact excerpt or abstention. No server processing, accounts, database, API calls, or document uploads.

This is a separate presentation of documented features. It does not expose the local product.

An honest scope

Evidence, with its limits in view.

The fixture is deliberately small and synthetic. It is not a benchmark for real-world accuracy. Word overlap can retrieve an irrelevant excerpt; an exact citation does not prove a claim is true.

  • No live ingestion, PDF parsing, OCR, or Python execution in this site.
  • No generated synthesis, semantic search, or cross-document reasoning.
  • Browser results are illustrative, not recorded Python evaluation results. JavaScript token normalization differs from Python casefolding.
  • No performance or general accuracy claims are made.
